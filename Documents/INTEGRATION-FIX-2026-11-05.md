# إصلاح تكامل النظام — 2026-11-05

## نطاق الإصلاح

عالج هذا التغيير عيوبًا مؤكدة بين واجهة الويب وAPI والخدمات وقاعدة البيانات:

- فرض عزل المصنع في خدمات دفعات الإنتاج لكل من القراءة حسب الطلب، والإنشاء، والتفاصيل، وتحديث الحالة والحذف. أصبح الوصول العام للمدير صريحًا، ولا يوسّع غياب FactoryId نطاق موظف المصنع. أُضيفت اختبارات تمنع القراءة والإنشاء عبر مصنع آخر، وتمنع ربط دفعة بنوع خرسانة غير نوع الطلب.
- مواءمة دفعات الإنتاج والمخزون مع DTOs وردود API الفعلية، واستخدام `ApiClient` المهيأ للمصادقة والعنوان الأساسي بدل `HttpClient` غير المهيأ. أضيفت قراءة تفاصيل الدفعة، واستُبدلت حقول نموذج الإنتاج القديمة بحقول النظام المحفوظة فعليًا.
- إصلاح مسارات الرحلات وأفعال HTTP وأغلفة `ApiResponse`، وإضافة دعم PATCH إلى `ApiClient`.
- ربط شاشة التوزيع بالرحلات عبر MVC proxy من نفس الأصل، مع antiforgery، بدل اعتماد JavaScript على كائن غير معرّف أو كشف JWT. وصُحح اختيار المصنع ليستخدم FactoryId، وجلب الطلبات المعتمدة من endpoint موجود مع فلتر المصنع والتاريخ.
- تقييد صفحات المخزون والإنتاج والتوزيع للأدوار التي يقبلها API. وأصبح Admin في المخزون يحدد المصنع عند الإنشاء، بينما يُفرض مصنع موظف المصنع من جلسة المستخدم.
- منع تشغيل `ProactiveAlertsWorker` في مضيفي الاختبارات؛ العامل الإنتاجي كان يستعلم قاعدة التطوير وقد يرسل إشعارات خارجية أثناء الاختبار.
- ضبط دقة Latitude وLongitude إلى `decimal(10,7)` وإضافة ترحيل يتحقق من المجال الجغرافي قبل تعديل الأعمدة.
