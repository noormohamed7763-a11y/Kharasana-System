## 📋 نظرة عامة على النظام

نظام **خراسانة (Kharasana ERP Ecosystem)** هو منظومة برمجية متكاملة تهدف إلى رقمنة وأتمتة دورة العمل الكاملة لمصانع الخرسانة الجاهزة ومحطات الخلط المركزية، بدءاً من استقبال طلبات العملاء والتسعير، مروراً بجدولة الرحلات وتتبع الخلاطات بالمضخات لحظياً، وصولاً إلى إدارة المخزون، خلطات الإنتاج، ومطابقة الصبات مالياً عبر كشوفات الحساب وسندات القبض المعتمدة.

تتكون المنظومة من 3 مكونات رئيسية متكاملة بشكل متناغم:
- **واجهة برمجة التطبيقات (Kharasana.API):** واجهة RESTful عالية الأداء مبنية بـ .NET 10، مستقلة تماماً، تدعم الإصدارات (`ApiVersioning`) والاتصال اللحظي لتتبع الشاحنات عبر (`SignalR / TrackingHub`) ومصممة لتغذية بوابة الويب وتطبيق الهاتف الذكي.
- **بوابة الويب الإدارية (Kharasana.Web):** لوحة تحكم وإدارة تفاعلية بنمط MVC مخصصة لمدير النظام العام (Admin) وموظفي المصانع (Factory Employees)، معتمدة بالكامل على اللغة العربية (RTL) مع تصميم عصري يعتمد على البطاقات التنفيذية ومؤشرات الأداء (KPIs).
- **تطبيق الهاتف الذكي (kharasana_app - Flutter):** تطبيق متعدد المنصات (Android & iOS) مخصص لـ **العملاء (Clients)** لإنشاء ومتابعة طلبات الصب ومعاينة السند الرسمي ومشاركة الموقع، ولـ **السائقين (Drivers)** لاستلام رحلات الصب، بدء التوصيل، بث الموقع الحي، وتأكيد التسليم.

   │     بوابة الويب الإدارية    │                   │   تطبيق الهاتف (Flutter)   │
   │      Kharasana.Web        │                   │       kharasana_app       │
   │ (مدير النظام + موظف المصنع) │                   │     (العميل + السائق)      │

## 🇾🇪 الخصائص والمواءمة مع البيئة والسوق اليمني

تم بناء النظام بدقة ليتعامل مع الخصوصية الميدانية والمالية لمصانع الخرسانة في اليمن:

### 1. العنونة بالمعالم البارزة والإحداثيات (Landmarks & GPS)
نظراً لغياب الترقيم البريدي الدقيق في المدن والمناطق اليمنية، يدعم النظام:
- توثيق **المعالم البارزة** لموقع الصب (مثل: جوار مدرسة كذا، خلف المستشفى، محطة وقود، إلخ).
- تسجيل إحداثيات الموقع الجغرافي (Latitude / Longitude) بدقة 6 خانات عشرية.
- زر تفاعلي فوري لفتح موقع الصب مباشرة في **خرائط Google Maps** لتوجيه سائقي الخلاطات والمضخات.

### 2. المواصفات الهندسية لخلطات الخرسانة اليمنية
- **أنواع الإسمنت المعتمدة محلياً:** بورتلاندي عادي (OPC)، مقاوم للكبريتات والأملاح (SRC - أساسي في المناطق الساحلية والمياه الجوفية الكبريتية)، وإسمنت بوزولاني.
- **مقاسات الركام (الكري والنيس):** تصنيف المقاسات وفق الدارج في الخلاطات المركزية (3/4 بوصة، 3/8 بوصة / فولية، مكسر، طبيعي).
- **المضافات الكيميائية (Admixtures):** مراعاة متطلبات الطقس والمسافات (ملدنات فائقة Superplasticizers، مؤخرات شك Retarders لتأخير التصلب أثناء الازدحامات وبعد المسافات، ومسرعات شك Accelerators).
- **مشرف الصب الميداني:** توثيق اسم ورقم هاتف مهندس/مشرف الموقع مع أزرار اتصال مباشر وإرسال رسالة **واتساب (WhatsApp)** ببيانات الصبة بنقرة زر واحدة.

### 3. المعاملات المالية والسندات والحوالات
- **العملة المحلية:** اعتماد **الريال اليمني (YER / ر.ي)** في كافة العمليات والتقارير.
- **التسعير المرن والتفضيلي:** مراعاة طبيعة التفاوض التجاري في السوق اليمني عبر ميزة *"طلب سعر تفضيلي / اكسبوني زبون"* مع إمكانية التسعير اليدوي للطلب المعتمد قبل الصب.
- **سندات الدفع والحوالات (Hawala / Cash Bonds):** دعم تسجيل الحوالات البنكية (الكريمي، النجم، إلخ) أو السندات النقدية، مع نظام تدقيق واعتماد الحوالات بواسطة المحاسب المالي وتوليد سندات قبض مطبوعة رسمياً.
- **مطابقة الصبات (Pour Reconciliation):** كشف حساب تفصيلي يقارن الكميات المصبوبة فعلياً مع السندات المسددة والرصيد الجاري للعميل.

### 4. شبكات الاتصالات وأرقام الهواتف اليمنية
- فحص وتحقق صارم من صحة أرقام الهواتف التابعة لجميع الشبكات اليمنية:
  - **يمن موبايل (Yemen Mobile):** البادئات `77` و `78`.
  - **يو (YOU):** البادئة `73`.
  - **سبأفون (Sabafon):** البادئة `71`.
  - **واي (Y Telecom):** البادئة `70`.
  - خطوط الهاتف الثابت والمصانع `01`، `02`، إلخ.

## ⚙️ الوحدات والأنظمة الفرعية (Core Modules)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Kharasana ERP Ecosystem                         │
├──────────────┬──────────────┬──────────────┬─────────────┬─────────────┤
│   الطلبات    │  الجدولة     │ خلطات الإنتاج│   المخزون   │  المالية    │
│  والتسعير    │  والرحلات    │  والتشغيل    │  والتنبيهات │  والمطابقة  │
└──────────────┴──────────────┴──────────────┴─────────────┴─────────────┘
```

### 1. إدارة الطلبات والتسعير (Order Lifecycle)
- دورة حياة كاملة: (جديد ⬅️ قيد الانتظار ⬅️ معتمد ⬅️ قيد الخلط ⬅️ قيد التوصيل ⬅️ تم التوصيل ⬅️ مكتمل / ملغى).
- حاسبة تقديرية فورية لتكاليف الخرسانة، أجور النقل، والمضخة حسب الطابق.
- إنشاء الطلبات الهاتفية المباشرة من قبل موظف المصنع نيابة عن العميل مع التحقق من عدم تكرار الطلبات المعلقة لنفس المشروع.
- طباعة أمر التوريد والصب (Delivery Ticket) بصيغة جاهزة للطباعة الميدانية.

### 2. جدولة الصبات وتوزيع الرحلات (Dispatch & Trips System)
- جدولة الطلبات المعتمدة حسب تاريخ ويوم الصب.
- تقسيم كمية الطلب الكبيرة على رحلات متعددة لخلاطات الخرسانة (Mixers) حسب سعة الشاحنة.
- تعيين السائق، رقم لوحة الخلاطة، تحديد توقيت التحرك، وطلب مضخة الخرسانة (Pump).

### 3. التتبع المباشر للخلاطات (Real-time Tracking with SignalR)
- مركز اتصال لحظي (`TrackingHub`) يتيح بث إحداثيات السائقين وسيارات النقل لحظة بلحظة.
- تحديث فوري لحالة رحلات الصب وسير العمل في شاشات الجدولة وغرفة العمليات.

### 4. خلطات الإنتاج (Production Batches)
- متابعة دفعات الإنتاج المرتبطة بأوامر التوريد والكميات المنتجة.
- ربط دقيق لنوع الخرسانة المطلوب بالمقاومة التصميمية ومتابعة حالة الخلط بالمحطة.

### 5. إدارة المخزون والمواد الخام والتنبيهات الاستباقية (Inventory & Alerts)
- جرد وتتبع أرصدة المواد الأولية للمصنع (الإسمنت، الركام، الرمل، والمضافات الكيميائية).
- **نظام تنبيهات استباقي آلي (`ProactiveAlertsWorker`):** خدمة خلفية دورية مستقلة تفحص أرصدة المواد الخام وتُطلق تحذيرات مبكرة عند هبوط الرصيد عن الحد الأدنى (`MinStockLevel`).

### 6. مطابقة الصبات ومكتب التدقيق المالي (Financial Ledger & Reconciliation)
- **كشف حساب العميل:** كشف مالي متكامل يربط الكميات المصبوبة، المبالغ المدينة، سندات الدفع الدائنة، والرصيد النهائي الجاري.
- **تدقيق الحوالات:** شاشة مخصصة للمحاسب لمراجعة الحوالات الواردة واعتمادها أو رفضها مع كتابة مبررات الرفض.
- **سندات القبض الرسمية:** توليد سندات قبض مالية برقم تسلسلي وطباعتها برقم المرجع وتفاصيل الدفعة.

### 7. بوابة التسجيل الذاتي للمصانع (Self-Service Factory Onboarding)
- واجهة عامة تتيح لأصحاب المصانع الجدد تقديم طلب انضمام للنظام مع وثائق السجل التجاري والبيانات التشغيلية.
- لوحة مراجعة مركزية لمدير النظام لدراسة طلبات الانضمام، والموافقة عليها وتجهيز بيئة المصنع تلقائياً.

## 🏛️ الهندسة المعمارية (Software Architecture)

تم تطبيق نمط **Clean Architecture (Onion Architecture)** الصارم لضمان الفصل التام بين منطق الأعمال وقواعد البيانات والواجهات:

```
                  ┌────────────────────────┐
                  │    Kharasana.Web       │ (MVC, ViewModels, Filters)
                  └───────────┬────────────┘
                              │ HTTP / JSON
                              ▼
                  ┌────────────────────────┐
                  │    Kharasana.API       │ (REST, SignalR, Middlewares)
                  └───────────┬────────────┘
                              │
     ┌────────────────────────┼────────────────────────┐
     ▼                        ▼                        ▼
┌──────────────┐     ┌──────────────────┐     ┌──────────────────┐
│Kharasana.Core│ ──► │  Kharasana.App   │ ◄── │  Kharasana.Infra │
│  (Domain)    │     │  (Application)   │     │ (Persistence/EF) │
└──────────────┘     └──────────────────┘     └──────────────────┘
```

- **`Kharasana.Domain`:** الكيانات الأساسية (`Order`, `Trip`, `ProductionBatch`, `RawMaterial`, `Factory`, `User`, `OrderPayment`)، المحددات (Enums)، وقواعد العمل النقية دون أي اعتماديات خارجية.
- **`Kharasana.Application`:** واجهات الخدمات والمستودعات (`Interfaces`)، الـ DTOs، منطق الأعمال، والتحقق عبر `FluentValidation`.
- **`Kharasana.Infrastructure`:** سياق قاعدة البيانات `KharasanaDbContext` (Entity Framework Core)، ترحيلات قاعدة البيانات (Migrations)، مستودعات البيانات عبر `IUnitOfWork`، التشفير، والخدمات الميدانية.
- **`Kharasana.API`:** طبقة التوزيع (Controllers, SignalR Hubs, Security Middlewares, Exception Handling).
- **`Kharasana.Web`:** واجهة المستخدم بنمط ASP.NET Core MVC مستهلكة للـ API عبر خدمة مرنة ومؤمنة بالكامل.

## 🛡️ الأمن والحماية الصارمة (Hardened Security Posture)

تم تدقيق وتحصين النظام بأعلى المعايير الأمنية العالمية:

| الآلية الأمنية | التطبيق والتأثير في نظام خراسانة |
|---|---|
| **Nonce-based Strict CSP** | سياسة أمان محتوى صارمة تُولّد رمز `Nonce` عشوائي مشفر لكل طلب، مع حظر كامل لكافة المعالجات المضمنة (`unsafe-inline`) والسكربتات الخارجية غير الموثوقة لمنع هجمات XSS. |
| **عزل المستأجرين (Tenant Isolation)** | عزل كامل لبيانات كل مصنع على مستوى استعلامات الـ Database عبر `Global Query Filters` وفلاتر التحقق في الـ Controllers لمنع تسريب بيانات المصانع لبعضها. |
| **دعم التعددية بالتبويبات (Multi-Tab Resilience)** | بنية جلسة آمنة تدعم عمل المستخدم على عدة تبويبات متزامنة دون حدوث تضارب في التوكن أو فشل رموز CSRF. |
| **التحكم بالتزامن (Optimistic Concurrency)** | تطبيق حقل `RowVersion` (Timestamp) لمنع الكتابة المتزامنة المتضاربة على السجلات الهامة. |
| **منع تكرار العمليات (Idempotency Control)** | دعم ترويسة `Idempotency-Key` في عمليات إنشاء الطلبات والدفعات لمنع الخصم أو التكرار عند انقطاع الاتصال. |
| **قواطع الدائرة وإعادة المحاولة (Resilience)** | استخدام `Microsoft.Extensions.Http.Resilience` مع `CircuitBreaker` و `RetryPolicies` لضمان استقرار الربط بين الويب والـ API. |
| **حماية الهجمات العنيفة (Rate Limiting)** | فرض قيود على معدلات استدعاء واجهات تسجيل الدخول والعمليات الحساسة. |
| **الحذف الآمن (Soft Delete)** | أرشفة الطلبات والمصانع والأنواع الخرسانية برمجياً دون فقدان تاريخ العمليات وسجلات الحسابات. |
| **الترويسات الأمنية المتقدمة** | تطبيق `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Permissions-Policy`, و `HSTS`. |

## 🎭 الأدوار والصلاحيات (Role-Based Access Control)

| الدور | الصلاحيات والمسؤوليات |
|---|---|
| **مدير النظام العام (Admin)** | إدارة شاملة للنظام: المصانع، طلبات الانضمام الجديدة، إدارة المستخدمين، إحصاءات المنظومة الشاملة، والتقارير العامة. |
| **موظف / مدير المصنع (FactoryEmployee)** | إدارة كاملة لعمليات مصنعه المعزول فقط: إنشاء وإدارة الطلبات، جدولة وتوزيع الرحلات، خلطات الإنتاج، إدارة المواد الخام والمخزون، مراجعة الحوالات المالية، كشوفات حساب ومطابقة صبات العملاء، وأنواع الخرسانة. |
| **العميل (Client)** | استعراض قائمة المصانع المتاحة، تقديم طلبات صب الخرسانة، متابعة حالة الطلب خطوة بخطوة، واستعراض كشف الحساب والمطابقة الخاصة به. |
| **السائق (Driver)** | استعراض رحلات التوصيل المسندة إليه، تفاصيل كمية الخلطة ونوعها، موقع الصب بالمعالم وخريطة Google، وتحديث حالة التسليم. |

## 🧪 التحقق والاختبارات الآلية (Testing Suite)

يحتوي النظام على حزمة اختبارات شاملة وموسعة تشمل:
- **اختبارات الوحدة (Unit Tests):** تغطي منطق الأعمال، التسعير، التحقق من الصلاحيات، وفلاتر العزل.
- **اختبارات التكامل (Integration Tests):** التحقق من سلامة قيود قاعدة البيانات (SQL Server)، فلاتر الحذف الناعم، وتحكم التزامن بالتفاؤل (`RowVersion`).
- **اختبارات العقود (Contract Tests):** ضمان توافق ردود الـ API مع واجهة الويب.

## 🚀 متطلبات التشغيل والبدء السريع (Quick Start)

### المتطلبات الأساسية
- [.NET 10.0 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)
- خادم **SQL Server** (محلي أو سحابي)
- Visual Studio 2022 / JetBrains Rider / VS Code

### خطوات الإعداد والتشغيل

1. **استنساخ المستودع وبناء الحل:**
   ```powershell
   git clone https://github.com/noormohamed7763-a11y/Kharasana.git
   cd Kharasana
   dotnet build
   ```

2. **تحديث قاعدة البيانات وتطبيق الترحيلات:**
   ```powershell
   dotnet ef database update --project Kharasana.Infrastructure --startup-project Kharasana.API
   ```

3. **تشغيل واجهة البرمجة (Kharasana.API):**
   ```powershell
   cd Kharasana.API
   dotnet run
   ```
   *يعمل الـ API افتراضياً على: `http://localhost:5000` (مع توثيق Swagger التفاعلي على `/swagger`).*
